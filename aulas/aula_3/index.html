Persistindo Dados: Entidades, Repositórios e o Primeiro CRUD

Conectando nossa API ao Banco de Dados com o Spring Data JPA.

Role para baixo para começar

1. A Entidade Java: Modelando a Tabela

Se a classe Java é a "planta" de uma casa, as anotações do JPA são as instruções para o pedreiro (o próprio JPA) construir a tabela no banco de dados automaticamente. Nós usamos anotações para dizer qual classe vai virar tabela e quais atributos serão colunas.

@Entity
public class Jogo {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    
    private String nome;
    private Double preco;

    // Getters e Setters
}

As Etiquetas Essenciais:

  • @Entity: "Avisando ao JPA que essa classe é uma tabela".
  • @Id: O RG/CPF único de cada registro.
  • @GeneratedValue(strategy = GenerationType.IDENTITY): O 'contador automático' do banco (Auto-Increment). O próprio banco cuida de gerar os números 1, 2, 3...

2. O Repositório JPA: O Almoxarife do Banco

Você não precisa escrever consultas SQL gigantescas à mão. O JpaRepository resolve a comunicação com o banco de forma transparente.

Pense nele como o Almoxarife. Você não precisa ir até o estoque (MySQL) buscar algo; você apenas pede ao almoxarife usando métodos como findAll() ou save() e ele traz o item pronto.

Para criar esse almoxarife, só precisamos criar uma interface que herda (extends) do `JpaRepository`.

public interface JogoRepository extends JpaRepository {
    // Pronto! Não precisa escrever código dentro da interface.
}

Como Funciona: Nós passamos dois parâmetros para o `JpaRepository`: o tipo da Entidade (Jogo) e o tipo do ID da Entidade (Long). Com isso, o Spring já gera todos os métodos básicos de CRUD por debaixo dos panos!

3. Injeção de Dependência (@Autowired): O Ramal Direto

Como a Recepcionista (nosso `@RestController`) conversa com o Almoxarife (o `@Repository`)?

Em Java puro, faríamos algo como JogoRepository repository = new JogoRepository();. Mas no Spring, nós usamos a Injeção de Dependência.

O Spring cria um ramal de telefone direto com a anotação @Autowired. Quando o Controller precisa do banco, o Spring já entrega a instância do repositório pronta para uso, sem precisarmos dar um new.

@RestController
@RequestMapping("/jogos")
public class JogoController {

    @Autowired
    private JogoRepository repository;
    
    // Métodos do CRUD...
}

4. Completando o CRUD no Controller

Agora vamos expandir a nossa rota /jogos para permitir criar, listar e deletar registros do banco de dados.

  • @GetMapping: Para listar. Retorna o resultado do repository.findAll().
  • @PostMapping: Para cadastrar. Combinamos com @RequestBody ("Abrindo o pacote JSON enviado pelo Front-End e convertendo em objeto Java"). Salvamos com repository.save().
  • @DeleteMapping: Para deletar. Usamos @PathVariable ("Pegando o ID passado diretamente na URL, ex: `/jogos/3`"). Deletamos com repository.deleteById().
@GetMapping
public List listar() {
    return repository.findAll();
}

@PostMapping
public Jogo salvar(@RequestBody Jogo jogo) {
    return repository.save(jogo);
}

@DeleteMapping("/{id}")
public void deletar(@PathVariable Long id) {
    repository.deleteById(id);
}
