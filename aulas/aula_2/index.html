Dominando o Spring Boot

Dando vida ao seu Back-End em Java de um jeito (Quem sabe) fácil!

Role para baixo para começar

1. O Spring Initializr e seus Componentes

Sabe quando você abre o VSCode, digita ! e aperta Tab para gerar toda aquela estrutura básica do HTML5? O Spring Initializr é exatamente isso, só que para o nosso Back-End em Java!

Ele é um site (um "gerador de projetos prontos") onde escolhemos as peças que queremos no nosso servidor. Para o nosso projeto, pegamos três ferramentas essenciais:

Spring Web

Pense nele como o garçom do nosso servidor. É ele que escuta quando o seu Front-End usa um fetch() no JavaScript, pega o pedido, leva para o Java e devolve a resposta (um JSON, por exemplo).

Spring Data JPA

É o tradutor mágico. O Java fala orientado a objetos, mas o Banco de Dados fala em tabelas SQL. O JPA traduz automaticamente as informações para que você não precise escrever comandos SQL gigantescos à mão!

MySQL Driver

É o cabo USB virtual. Ele é o código que literalmente permite que o Java consiga se plugar e fazer uma conexão física com o banco de dados MySQL que está rodando no seu computador.

2. O poder do "@" (Annotations)

Antes de olharmos para o código Java, precisamos falar sobre o símbolo @. Esqueça o arroba do Instagram ou do e-mail por um instante.

No Java, uma anotação (Annotation) é como uma etiqueta de superpoderes. Pense num videogame: se você colar a etiqueta @Fogo na sua espada, ela ganha poderes de fogo, sem você precisar reprogramar a espada inteira.

Se você tem uma classe simples chamada Aluno e coloca um @Entity em cima dela, o Java olha para aquela etiqueta e diz: "Opa! Essa classe tem o superpoder de virar uma tabela no banco de dados!".

Usamos as etiquetas para dar instruções complexas ao Spring Boot escrevendo apenas uma única palavrinha. É como usar classes CSS prontas (tipo no Bootstrap) para estilizar algo instantaneamente!

3. O Arquivo application.properties

Esse arquivo é o Painel de Controle da sua nave. É aqui que passamos as configurações para o nosso projeto funcionar. Estamos usando três configurações cruciais:

spring.datasource.username=root
spring.datasource.password=univille
spring.datasource.url=jdbc:mysql://localhost:3306/TimeOutZone?useSSL=false&serverTimezone=UTC
  • username e password: É o login e a senha do seu banco de dados MySQL (no caso, o usuário "root" e a senha "univille"). Se errar aqui, o Java não consegue entrar no banco!
  • url: É o endereço de *onde* o banco de dados está. localhost:3306 significa "meu próprio computador na porta 3306", e /TimeOutZone é o nome exato do banco que estamos criando.

E o que é esse useSSL=false?

O SSL é o cadeado de segurança (o 'S' do HTTPS) que criptografa os dados para ninguém hackear. Como estamos programando e testando apenas dentro do nosso próprio computador (ambiente local), desligamos isso (false) para não termos dor de cabeça configurando certificados. Em um servidor real na internet, isso ficaria ativado!

Outras configurações comuns aqui: server.port=8080 (para mudar a porta do nosso servidor) e spring.jpa.show-sql=true (para o Java mostrar no console todos os comandos SQL que ele está fazendo escondido).

4. A Classe Principal do Java

No Front-end, o navegador sempre procura o arquivo index.html primeiro para começar a desenhar a tela, certo? No nosso Back-End, o Spring Initializr gera uma Classe Principal que tem esse mesmo papel.

@SpringBootApplication
public class TimeOutZoneApplication {
    public static void main(String[] args) {
        SpringApplication.run(TimeOutZoneApplication.class, args);
    }
}

Ela é o pontapé inicial do servidor. Quando você aperta "Play" (Run) no seu editor, o Java procura exatamente o método main dessa classe para acordar a aplicação.

E olhe lá em cima: a etiqueta @SpringBootApplication. É o superpoder supremo que avisa o Java: "Ei, acorde todos os componentes, ligue o servidor web e conecte no banco de dados agora!".

5. Criando Rotas: @RestController e @GetMapping

Como o Front-End (JavaScript) consegue puxar os dados do Java? Precisamos criar "portas de atendimento" chamadas Endpoints ou Rotas.

  • @RestController: Colocamos essa etiqueta na classe para transformá-la numa "Recepcionista". Ela avisa o Spring: "Essa classe vai receber pedidos HTTP (do Front-End) e devolver arquivos JSON".
  • @GetMapping: Define o endereço exato para buscar dados. Pense na URL como o caminho das pastas no seu PC.
@RestController
public class JogosController {

    @GetMapping("/jogos")
    public String listarJogos() {
        return "Aqui estão seus jogos!";
    }
}

Conectando os pontos: Quando você faz um fetch('http://localhost:8080/jogos') lá no seu arquivo script.js do Front-End, o @RestController recebe a visita, o @GetMapping("/jogos") abre a porta certa, e a mensagem volta para a sua tela!
