Do Formulário ao MySQL: Nossa Primeira Aplicação Completa

Front-end, Spring Boot e Banco de Dados conversando entre si. Vamos construir tudo do zero e entender cada peça.

Role para baixo para começar

O Plano: Um Restaurante de Espiões

Imagine um restaurante. O cliente (navegador) faz o pedido, o garçom (Spring Boot) leva até a cozinha e o estoque (MySQL) guarda os ingredientes. O cliente digita uma agência (CIA, MOSSAD ou ABIN) e recebe a lista de espiões dela.

  • Model: os "moldes" dos dados (Agencia, Espiao).
  • View: o que o usuário vê. Aqui é o index.html, que fica em outra pasta.
  • Controller: o garçom, que recebe pedidos e responde.
  • Repository: o estoquista, que fala com o banco.

1. O Banco de Dados: O Estoque e o Dump SQL

Um banco de dados relacional é um conjunto de tabelas (como planilhas) ligadas entre si. O arquivo database/schema.sql é um dump (despejo): um roteiro em SQL que, ao ser executado, cria o banco, as tabelas e os dados iniciais. Quem receber o arquivo reconstrói o mesmo banco.

No VS Code, com a extensão MySQL Database Client, conecte no seu servidor MySQL, abra o schema.sql e execute o arquivo inteiro (Run All).

CREATE DATABASE IF NOT EXISTS agencias_db;
USE agencias_db;

CREATE TABLE Agencia (
 id_agencia INT AUTO_INCREMENT PRIMARY KEY,
 nome_agencia VARCHAR(100) NOT NULL
);
CREATE TABLE Missao (
 id_missao INT AUTO_INCREMENT PRIMARY KEY,
 nome_missao VARCHAR(150) NOT NULL UNIQUE,
 descricao TEXT
);
CREATE TABLE Espiao (
 id_espiao INT AUTO_INCREMENT PRIMARY KEY,
 nome_real VARCHAR(150) NOT NULL,
 nome_espiao VARCHAR(100) DEFAULT '007',
 descricao TEXT,
 id_agencia INT NOT NULL,
 id_missao INT,
 FOREIGN KEY (id_agencia)
   REFERENCES Agencia(id_agencia),
 FOREIGN KEY (id_missao)
   REFERENCES Missao(id_missao)
);
  • PRIMARY KEY: o "CPF" da linha, único.
  • AUTO_INCREMENT: o banco numera sozinho (1, 2, 3...).
  • NOT NULL: não pode ficar vazio. UNIQUE: não pode repetir. DEFAULT: valor usado se ninguém informar (todo espião sem nome fica "007").
  • FOREIGN KEY (chave estrangeira): o "crachá de outra tabela". Espiao.id_agencia aponta para uma linha de Agencia. O banco recusa um espião de agência inexistente.
  • A USE agencias_db; escolhe o banco padrão da sessão. Depois vêm os INSERT INTO com CIA, MOSSAD, ABIN, as missões e 5 espiões de exemplo.

Teste: SELECT * FROM Agencia; deve mostrar CIA, MOSSAD e ABIN. Note que o espião guarda só o número da agência, não o nome. Isso é importante mais à frente.

2. Spring Initializr: A Caixa de Montar

Um framework é um "kit de montar": em vez de escrever tudo, você recebe peças prontas. O Spring Boot é o kit de Java para criar aplicações web. O Spring Initializr (start.spring.io) é o site que monta a caixa inicial para você.

  • Project: Maven: ferramenta que baixa as bibliotecas e compila. Ela lê o pom.xml, a "lista de compras" do projeto.
  • Language: Java. Packaging: Jar (o programa empacotado).
  • Spring Boot: versão estável (sem SNAPSHOT, M ou RC).
  • Group: com.example. Artifact: agencia. Juntos formam o pacote com.example.agencia.
  • Java: 21 (versão LTS, suporte longo).

Dependências (bibliotecas):

  • Spring Web: traz o Tomcat (servidor web embutido) e as ferramentas para receber pedidos HTTP e responder em JSON.
  • Spring Data JPA: traz o Hibernate, que traduz objetos Java para SQL.
  • MySQL Driver: o "tradutor" que sabe falar o idioma do MySQL.

Clique em Generate, extraia o .zip e coloque o conteúdo dentro de back-end/, de modo que o pom.xml fique direto lá, sem pasta extra no meio.

3. application.properties: O Cartão de Visitas do Banco

Para o Java achar o MySQL, ele precisa de endereço, usuário e senha. Isso fica em src/main/resources/application.properties, um arquivo de configuração no formato chave=valor.

spring.datasource.url=jdbc:mysql://localhost:3306/agencias_db
spring.datasource.username=root
spring.datasource.password=SUA_SENHA
spring.jpa.hibernate.ddl-auto=none
spring.jpa.show-sql=true
  • url: jdbc:mysql (protocolo), localhost (este computador), 3306 (a "porta" do MySQL, como o número de uma janela de atendimento), agencias_db (qual banco). JDBC é o padrão do Java para falar com bancos.
  • username/password: valor direto, sem aspas e sem espaço sobrando no fim.
  • ddl-auto=none: "Hibernate, não mexa nas tabelas, eu já criei no dump".
  • show-sql=true: imprime no terminal cada SQL que o Spring executa. Ótimo para aprender!

Esqueceu a senha? O MySQL guarda só um hash (embaralhado sem volta). Crie um usuário novo: CREATE USER 'agencias_user'@'localhost' IDENTIFIED BY 'senha'; e GRANT ALL PRIVILEGES ON agencias_db.* TO 'agencias_user'@'localhost';

4. AgenciaApplication: O Botão de Ligar

package com.example.agencia;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication
public class AgenciaApplication {
    public static void main(String[] args) {
        SpringApplication.run(AgenciaApplication.class, args);
    }
}
  • package: o endereço (pasta) da classe.
  • import: "vou usar a ferramenta tal, que mora em tal pacote".
  • main: o ponto de partida de todo programa Java. É o botão de ligar.
  • SpringApplication.run(...): acorda o Spring. Ele escaneia as subpastas, acha suas classes, conecta no MySQL e sobe o Tomcat na porta 8080.
  • @SpringBootApplication: etiqueta que significa "esta é a classe principal; comece a procurar aqui".

Como rodar: botão Run acima do main no VS Code (precisa do Extension Pack for Java) ou .\mvnw spring-boot:run dentro de back-end/. Sucesso = Started AgenciaApplication in X seconds. Para parar, clique no quadrado vermelho.

5. Model: O Molde da Tabela

Uma classe Java é uma "planta de casa". Uma Entity é uma classe cujos objetos representam linhas de uma tabela. Cada atributo vira uma coluna. Isso se chama, na Computação, ORM (Mapeamento Objeto-Relacional): ligar o mundo dos objetos ao mundo das tabelas.

@Entity
@Table(name = "Espiao")
public class Espiao {
  @Id
  @GeneratedValue(strategy =
     GenerationType.IDENTITY)
  @Column(name = "id_espiao")
  private Integer id;

  @Column(name = "nome_real")
  private String nomeReal;

  @Column(name = "nome_espiao")
  private String nomeEspiao;

  @Column(name = "descricao")
  private String descricao;

  // id_agencia é só o NÚMERO da chave
  // estrangeira, não a agência em si.
  @Column(name = "id_agencia")
  private Integer idAgencia;

  // getters...
}
  • @Entity: "esta classe é uma tabela". Sem ela o JPA ignora a classe.
  • @Table(name=...): nome real da tabela no banco.
  • @Id: o campo que é a chave primária.
  • @GeneratedValue(IDENTITY): o banco gera o número (AUTO_INCREMENT).
  • @Column(name=...): liga o atributo à coluna. Java usa nomeReal (camelCase), o banco usa nome_real.
  • private: só a própria classe mexe direto. Getters são as "janelinhas" de leitura e o Jackson, que gera o JSON, precisa deles.

Agencia.java é igual, com duas colunas: id (id_agencia) e nomeAgencia (nome_agencia). Deixamos id_missao de fora de propósito: não vamos precisar nesta consulta.

6. Repository: O Estoquista (e o SQL escondido)

public interface AgenciaRepository extends JpaRepository<Agencia, Integer> {
    // SELECT * FROM Agencia WHERE nome_agencia = ?
    Agencia findByNomeAgencia(String nomeAgencia);
}

public interface EspiaoRepository extends JpaRepository<Espiao, Integer> {
    // SELECT * FROM Espiao WHERE id_agencia = ?
    List<Espiao> findByIdAgencia(Integer idAgencia);
}
  • interface: só um contrato ("o que fazer"), sem o "como". O Spring escreve a implementação sozinho enquanto o programa liga.
  • extends JpaRepository: herda de graça findAll() (SELECT * FROM Espiao), findById(1) (... WHERE id_espiao = 1), save() (INSERT ou UPDATE), deleteById() (DELETE) e count().
  • <Agencia, Integer>: generics, dois "espaços em branco" a preencher: 1º o tipo da entidade, 2º o tipo da chave primária. A JpaRepository pede exatamente dois.
  • findBy + NomeDoCampo: método derivado. O Spring lê o nome do método e monta o SQL. O nome é o do campo Java (nomeAgencia), não o da coluna. Se errar, a aplicação nem liga.
  • List<Espiao>: vários espiões podem ter a mesma agência, por isso a lista. Já o nome da agência é único, então volta um só objeto (ou null).

Na prática: o Hibernate gera algo como select e1_0.id_espiao, e1_0.nome_real ... from Espiao e1_0 where e1_0.id_agencia=? e usa um PreparedStatement (o ? recebe o valor com segurança, evitando SQL Injection). Confira no terminal graças ao show-sql: as linhas começam com Hibernate:.

7. Controller: O Garçom

@RestController
@CrossOrigin
public class EspiaoController {
  private final AgenciaRepository agenciaRepository;
  private final EspiaoRepository espiaoRepository;

  public EspiaoController(AgenciaRepository a, EspiaoRepository e) {
    this.agenciaRepository = a;
    this.espiaoRepository = e;
  }

  @GetMapping("/espioes")
  public ResponseEntity<List<Espiao>> buscarPorAgencia(
        @RequestParam String agencia) {
    // SELECT * FROM Agencia WHERE nome_agencia = ?
    Agencia ag = agenciaRepository
        .findByNomeAgencia(agencia.toUpperCase());
    if (ag == null) {
      return ResponseEntity.notFound().build();
    }
    // SELECT * FROM Espiao WHERE id_agencia = ?
    List<Espiao> lista = espiaoRepository
        .findByIdAgencia(ag.getId());
    return ResponseEntity.ok(lista);
  }
}
  • @RestController: "esta classe atende pedidos HTTP e responde com dados (JSON), não com páginas".
  • @CrossOrigin: o navegador, por segurança (CORS), bloqueia uma página de uma "origem" de chamar outra origem. Essa etiqueta faz o Java responder "pode deixar, eu autorizo".
  • Construtor com os repositories: injeção de dependência. Você não dá new: o Spring entrega os objetos prontos, como um "ramal direto" com o estoquista.
  • @GetMapping("/espioes"): "pedidos GET para /espioes vêm para este método".
  • @RequestParam: pega o ?agencia=CIA da URL.
  • ResponseEntity: a resposta HTTP completa (status + corpo). notFound().build() = status 404 sem corpo. ok(lista) = status 200 com a lista, que o Jackson converte em JSON.
Há um custo em realizar a operação desse jeito: estamos fazendo duas consultas no Banco de Dados (é mais lento).

8. Atalho Consciente: O Jeito Certo Seria o JOIN

No Espiao, usamos Integer idAgencia. O jeito correto é declarar que cada espião tem uma Agencia (objeto), usando @ManyToOne ("muitos espiões para uma agência") e @JoinColumn ("a chave estrangeira é esta coluna"):

@ManyToOne
@JoinColumn(name = "id_agencia")
private Agencia agencia;

// no repository:
List<Espiao> findByAgenciaNomeAgencia(
        String nome);
-- Uma consulta só, com JOIN:
SELECT e.*
FROM Espiao e
JOIN Agencia a
  ON e.id_agencia = a.id_agencia
WHERE a.nome_agencia = 'CIA';

9. index.html: A Vitrine

<form method="GET">
  <input type="text" name="agencia">
  <button type="submit">Buscar</button>
</form>
<p id="resultado"></p>

<script>
const form = document.querySelector('form');
const resultado = document.querySelector('#resultado');

async function buscar(event) {
  event.preventDefault();
  const agencia = form.agencia.value;
  const resposta = await fetch(
    `http://localhost:8080/espioes?agencia=${encodeURIComponent(agencia)}`);
  if (!resposta.ok) { resultado.textContent = 'Agência não encontrada.'; return; }
  const espioes = await resposta.json();
  let texto = '';
  for (const e of espioes) {
    texto += `${e.nomeEspiao} (${e.nomeReal}): ${e.descricao}\n`;
  }
  resultado.textContent = texto;
}
form.addEventListener('submit', buscar);
</script>
  • addEventListener('submit', buscar): "quando o formulário for enviado, chame buscar". Sem parênteses: entregamos a função para o navegador chamar depois.
  • preventDefault(): o submit normal recarregaria a página e perderíamos a resposta.
  • async / await: a resposta demora (rede + banco). await pausa só esta função até chegar, sem travar a página.
  • fetch: o navegador faz um pedido HTTP. encodeURIComponent troca caracteres perigosos da URL por códigos %XX.
  • resposta.ok é false no 404. resposta.json() converte o JSON em objetos JavaScript.
  • Um <p> ignora o \n, por isso o CSS #resultado { white-space: pre-line; }.

10. O Caminho Completo de um Pedido

Você digita CIA e clica em Buscar. A explicação simples é "o pedido vai e a resposta volta". Mas na prática, de fato, acontece isto (ida, depois volta):

Ida

  • 1. Navegador: o evento submit dispara buscar. O fetch monta o pedido GET /espioes?agencia=CIA.
  • 2. Rede local (loopback): localhost é o nome do endereço 127.0.0.1, "este próprio computador". Navegador, Java e MySQL são programas (processos) separados, cada um com sua memória privada. Eles não compartilham memória: conversam por sockets (portas) do sistema operacional, que copia os bytes de um para o outro. O protocolo TCP garante que cheguem inteiros e em ordem.
  • 3. Porta 8080 / Tomcat: quem escuta a porta 8080 é o Tomcat, o servidor embutido (software oculto nº 1). Ele lê o texto HTTP (GET /espioes?agencia=CIA + cabeçalhos, incluindo Origin).
  • 4. DispatcherServlet: o "recepcionista" do Spring (software oculto nº 2) vê a rota /espioes e escolhe o método com @GetMapping("/espioes"). Extrai CIA (@RequestParam).
  • 5. Controller: executa findByNomeAgencia("CIA"). Na verdade o repository é um objeto proxy (um "dublê") criado pelo Spring.
  • 6. Hibernate (ORM): traduz a chamada em SQL: select ... from Agencia where nome_agencia=?.
  • 7. HikariCP + JDBC: abrir conexão é lento, então o Spring mantém um pool de conexões abertas (HikariCP). Pega uma emprestada. O MySQL Driver traduz o pedido para o protocolo do MySQL.
  • 8. Rede de novo: socket TCP na porta 3306 até o processo mysqld.
  • 9. MySQL: confere usuário e senha, analisa o SQL, usa os índices e lê os dados do disco (ou do cache em memória), achando a linha da CIA (id 1).

Volta

  • 10. O MySQL devolve as linhas pelo socket. O driver monta um ResultSet, e o Hibernate o transforma em objeto Agencia. A conexão volta ao pool.
  • 11. O controller usa ag.getId() e repete os passos 5 a 10 com select ... from Espiao where id_agencia=?. Voltam objetos Espiao numa List.
  • 12. Jackson: converte a lista em texto JSON usando os getters ([{"nomeEspiao":"Falcon",...}]). É a serialização.
  • 13. O Spring monta a resposta HTTP: status 200 OK, cabeçalhos (incluindo Access-Control-Allow-Origin, por causa do @CrossOrigin) e o JSON no corpo. O Tomcat envia pelo socket.
  • 14. Navegador: confere o CORS. Se estiver autorizado, a promessa do fetch é resolvida, o await continua, resposta.json() reconstrói os objetos JS, o for monta o texto e o textContent o mostra no <p>.

Para o 404: no passo 5, findByNomeAgencia devolve null, o controller responde notFound(), o resposta.ok dá false e o JS escreve "Agência não encontrada." Só uma consulta SQL foi feita.
