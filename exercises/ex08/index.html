Como será na prova

No simulado, a estrutura já vem pronta. Na prova, você monta ela sozinho:

  1. Crie uma pasta chamada prova e, dentro dela, as pastas backend, frontend e database.
  2. Baixe o projeto gerado no Spring Initializr (demo.zip) e extraia o conteúdo dele dentro de backend.
  3. Coloque o dump.sql em database e o index.html em frontend.
  4. Configure o application.properties (próxima seção).
  5. Rode o dump.sql no Database Client, rode o Spring Boot e abra o index.html no navegador.

Configurando o application.properties

Abra backend/src/main/resources/application.properties e deixe assim, trocando trocar_usuário e trocar_senha pelo usuário e senha do seu MySQL: 

spring.application.name=demo
spring.datasource.url=jdbc:mysql://localhost:3306/filmes_db
spring.datasource.username=trocar_usuário
spring.datasource.password=trocar_senha
3306 ou 8080? São duas portas diferentes, cuidado para não trocar:
  • 3306 é a porta do MySQL. É ela que vai no application.properties, porque é onde o Spring busca os dados.
  • 8080 é a porta do Tomcat, o servidor que roda dentro do Spring Boot. É ela que vai no fetch do front-end (http://localhost:8080/...), porque é onde o front busca o Spring.
filmes_db é o nome do banco criado pelo dump.sql.

O banco de dados

O catálogo tem 5 tabelas, todas ligadas entre si:

Esquema EER (feito no TerraER)

Tabela O que guarda Chave estrangeira
Genero Terror, Suspense, Ficção Científica, Comédia, Animação —
Diretor Nome e nacionalidade do diretor —
Filme Título, ano, duração, classificação indicativa e sinopse id_genero e id_diretor (ambas NOT NULL)
Usuario Nome e e-mail de quem usa o site —

Cadê as chaves estrangeiras no desenho? No EER elas não aparecem como atributo: quem representa a ligação é o losango. O losango pertence (Filme N : 1 Gênero) vira a coluna id_genero na tabela Filme, porque a chave estrangeira sempre fica do lado N. No Java, ela vira o atributo private Genero genero; com @ManyToOne.

Dica: nos exercícios você vai apagar e alterar dados. Para voltar tudo ao normal, é só rodar o dump.sql inteiro de novo (ele apaga e recria o filmes_db).

Novidade: POST, PUT e DELETE

Cada operação do CRUD tem o seu verbo HTTP e a sua anotação no Spring:

Verbo Para quê Anotação Método do repository
GET Buscar (já sabemos) @GetMapping findAll(), findById(), @Query
POST Cadastrar algo novo @PostMapping save(obj) com obj sem id → INSERT
PUT Alterar algo que já existe @PutMapping save(obj) com obj com id → UPDATE
DELETE Apagar @DeleteMapping deleteById(id)
De onde vem o dado? O Spring pode ler a informação de três lugares:
  • @RequestParam: da query string, depois do ?. Ex.: /filmes/genero?nome=Terror
  • @PathVariable: de um pedaço da própria URL, marcado com { }. Ex.: @DeleteMapping("/avaliacoes/{id}") e a URL /avaliacoes/3
  • @RequestBody: do corpo da requisição, em JSON. O Spring converte o JSON em um objeto Java (as chaves do JSON precisam ter o mesmo nome dos atributos da classe).
E no front-end? Até agora o fetch recebia só a URL (e isso é sempre um GET). Para os outros verbos, passamos um segundo parâmetro com as opções: 
const resposta = await fetch(`http://localhost:8080/jogos`, {
    method: 'POST',                                   // o verbo: 'POST', 'PUT' ou 'DELETE'
    headers: { 'Content-Type': 'application/json' },  // avisa o Spring: "o corpo é JSON"
    body: JSON.stringify(jogo)                        // objeto JavaScript → texto JSON
});
O DELETE não precisa de headers nem body: só do method.
Atenção: a barra do navegador só faz GET. Então POST, PUT e DELETE não dá para testar digitando a URL: teste pelo front-end (e confira o resultado com as consultas GET).
Respostas do back-end: ResponseEntity.ok("...") = 200 (deu certo), ResponseEntity.notFound().build() = 404 (não existe, sem mensagem) e ResponseEntity.badRequest().body("...") = 400 (o pedido veio errado, com mensagem). No front, !resposta.ok pega o 404 e o 400.

Exercícios Práticos

Realize os exercícios abaixo em ordem crescente de dificuldade. Cada um tem o seu card pronto no front-end; os comentários no <script> dizem os ids dos campos.

1. Aquecimento: filmes de um diretor GET

Crie o endpoint /filmes/diretor?nome=John Carpenter, que devolve os filmes daquele diretor.

  • O modelo é a busca por gênero. No FilmeRepository, crie buscarPorDiretor com @Query em JPQL: JOIN FETCH f.genero JOIN FETCH f.diretor d WHERE d.nomeDiretor = :nomeDiretor e @Param.
  • No FilmeController, use @GetMapping e @RequestParam.
  • Por que dois JOIN FETCH? O front mostra o gênero e o diretor de cada filme, então os dois precisam vir junto.
  • No front, crie a async function buscarPorDiretor (dá para reaproveitar a função exibirFilmes).
  • Pode ser testado direto na barra do navegador. John Carpenter tem 2 filmes no catálogo.

2. Apagar uma avaliação DELETE

No AvaliacaoController, crie DELETE /avaliacoes/{id}, que apaga a avaliação com aquele id.

Exemplo com o Jogo da aula 3: 
@DeleteMapping("/jogos/{id}")
public ResponseEntity<String> apagar(@PathVariable Integer id) {
    if (!jogoRepository.existsById(id)) {       // não existe? 404
        return ResponseEntity.notFound().build();
    }
    jogoRepository.deleteById(id);
    return ResponseEntity.ok("Jogo " + id + " apagado.");
}
O {id} da URL e o parâmetro Integer id precisam ter o mesmo nome.
  • No front, use fetch(..., { method: 'DELETE' }) e mostre o texto da resposta com await resposta.text().
  • Para testar: veja as avaliações do filme 1, apague uma delas pelo id (o número depois do #) e veja de novo.
Para pensar: no Database Client, tente DELETE FROM Filme WHERE id_filme = 1;. O MySQL não deixa. Por quê? O que precisaria acontecer antes para conseguir apagar esse filme?

3. Cadastrar um diretor POST

No DiretorController, crie POST /diretores (cadastra) e GET /diretores (lista todos, para conferir).

Exemplo com o Jogo: 
@PostMapping("/jogos")
public ResponseEntity<String> cadastrar(@RequestBody Jogo jogo) {
    Jogo salvo = jogoRepository.save(jogo);    // sem id → INSERT
    return ResponseEntity.ok("Jogo cadastrado com id " + salvo.getId());
}
O @RequestBody pega o JSON { "nome": "Minecraft", "preco": 99.9 } e entrega um objeto Jogo pronto. Depois do save, o objeto volta com o id que o MySQL gerou (AUTO_INCREMENT).
  • No front, monte o objeto com as chaves iguais aos atributos da classe Diretor: { nomeDiretor: ..., nacionalidade: ... }, e envie com method: 'POST', headers e body: JSON.stringify(...).
  • O GET /diretores só precisa do findAll(), que já vem no JpaRepository. Teste na barra do navegador.
  • O botão "Listar diretores" não é um submit: use addEventListener('click', ...).

4. Editar uma avaliação PUT

No AvaliacaoController, crie PUT /avaliacoes/{id}, que altera a nota e o comentário de uma avaliação.

O PUT tem 3 passos: buscar, alterar e salvar. O id vem na URL (@PathVariable) e os novos dados vêm no corpo (@RequestBody): 
@PutMapping("/jogos/{id}")
public ResponseEntity<String> atualizar(@PathVariable Integer id, @RequestBody Jogo dados) {
    Jogo jogo = jogoRepository.findById(id).orElse(null);   // 1. buscar
    if (jogo == null) {
        return ResponseEntity.notFound().build();
    }
    jogo.setPreco(dados.getPreco());                        // 2. alterar
    jogoRepository.save(jogo);                              // 3. salvar (tem id → UPDATE)
    return ResponseEntity.ok("Jogo " + id + " atualizado.");
}
O findById devolve um Optional (uma "caixa" que pode estar vazia). O .orElse(null) abre a caixa: se estiver vazia, devolve null.
  • A classe Avaliacao só tem getters. Para alterar, crie setNota e setComentario.
  • Se a nota não estiver entre 0 e 10, devolva ResponseEntity.badRequest().body("A nota deve ser de 0 a 10.").
  • No front, use method: 'PUT', o id na URL e { nota, comentario } no body. Use Number(...) para transformar a nota em número.
  • O 404 vem sem texto, mas o 400 vem com a mensagem do back-end: mostre await resposta.text() quando ela não estiver vazia.

5. Avaliar um filme POST com chave estrangeira

No AvaliacaoController, crie POST /avaliacoes, que cadastra uma avaliação nova ligada a um filme e a um usuário.

Como mandar a chave estrangeira? Na classe Avaliacao, filme e usuario não são números: são objetos (lembra do @ManyToOne?). Então, no JSON, eles também viram objetos com o id dentro: 
{
    "nota": 9,
    "comentario": "Clássico!",
    "filme":   { "id": 13 },
    "usuario": { "id": 4 }
}
O @RequestBody Avaliacao avaliacao monta tudo, e o save grava id_filme = 13 e id_usuario = 4 na tabela.
  • Antes de salvar, confira com existsById se o filme (avaliacao.getFilme().getId()) e o usuário existem. Se não existirem, devolva badRequest com uma mensagem.
  • Valide a nota (0 a 10) como no exercício 4.
  • Para testar: o filme 13 (À Meia-Noite Levarei Sua Alma) não tem nenhuma avaliação. Veja o resumo dele, avalie e veja o resumo de novo: "sem avaliações" vira a nota média.

Lembretes

Extraia o .zip em uma pasta no seu computador (Área de Trabalho, por exemplo) e abra essa pasta no VS Code (Arquivo → Abrir Pasta...).

Lembre-se: de baixar as extensões no VS Code: Extension Java Pack (EJP), Database Client (DC).

Lembre-se: é preciso configurar o application.properties do Spring Boot com o usuário e a senha do banco de dados.

Lembre-se: é preciso configurar o Database Client com a senha do banco de dados (também).

Se as extensões estiverem corretas, o EJP fará imports automáticos (inclusive de @PostMapping, @PathVariable etc.), ajudará com a sintaxe, e o DC facilitará as consultas no MySQL, permitindo que sejam feitas direto pelo VS Code.
