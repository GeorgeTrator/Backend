Exercício 03 — Conectando Java ao MySQL

Neste exercício vamos conectar uma aplicação Java ao nosso banco de dados MySQL. Diferente dos exercícios anteriores, aqui a ideia é colocar a mão na massa: baixar o projeto já pronto na estrutura correta, configurar no VS Code e rodar de verdade uma inserção e uma busca no banco de dados.

Baixe o projeto

📦 projeto-base.zip

Já vem com as pastas lib/, src/util/ e src/model/ organizadas.

Baixar projeto (.zip)

Extraia o .zip em uma pasta no seu computador (Área de Trabalho, por exemplo) e abra essa pasta no VS Code (Arquivo → Abrir Pasta...).

Passo a passo

Passo 1 — Instalar a extensão do Java

No VS Code, vá até a aba de Extensões e instale o pacote Extension Pack for Java (da Microsoft). Isso adiciona o suporte necessário para rodar código Java direto pelo botão Run.

Passo 2 — Vincular o driver do MySQL (.jar)

O projeto que você baixou já vem com o arquivo mysql-connector-j.jar dentro da pasta lib/. Precisamos avisar o VS Code que esse arquivo existe:

  • No painel Explorer (lado esquerdo), role até Java Projects.
  • Passe o mouse sobre Referenced Libraries e clique no ícone +.
  • Selecione o arquivo .jar que está dentro de lib/.
Por que essa pasta lib/? Java sozinho não sabe conversar com o MySQL. Esse arquivo .jar é o "tradutor" (chamado de driver) que permite que o Java envie e receba dados do banco. Colocamos ele em uma pasta separada (lib/, de "library") só para deixar organizado e separado do nosso próprio código.

Passo 3 — Criar o banco de dados no MySQL

Abra o MySQL (Workbench, terminal ou a ferramenta que estiver usando) e rode o script abaixo para criar a tabela de teste: 

CREATE DATABASE IF NOT EXISTS sistema_db;
USE sistema_db;

CREATE TABLE IF NOT EXISTS usuarios (
    id INT AUTO_INCREMENT PRIMARY KEY,
    nome VARCHAR(100) NOT NULL,
    email VARCHAR(100) NOT NULL
);

INSERT INTO usuarios (nome, email) VALUES ('Carlos Silva', 'carlos@email.com');

Passo 4 — Configurar a conexão

Abra o arquivo src/util/Conexao.java (ele já está pronto no projeto) e troque USER e PASS pelo usuário e senha do seu MySQL: 

package util;

import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.SQLException;

public class Conexao {
    private static final String URL = "jdbc:mysql://localhost:3306/sistema_db?useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=UTC";
    private static final String USER = "root";     // troque pelo seu usuario do MySQL
    private static final String PASS = "sua_senha"; // troque pela sua senha do MySQL

    public static Connection getConexao() throws SQLException {
        return DriverManager.getConnection(URL, USER, PASS);
    }
}
O que é essa Connection? Pense nela como uma "ligação telefônica" aberta entre o seu programa Java e o banco de dados. Enquanto ela estiver aberta, dá pra mandar comandos SQL (inserir, buscar, etc). No fim, é importante desligar essa ligação — é isso que o try (...) do próximo passo faz automaticamente por nós.

Passo 5 — Entender a pasta model/ (DAO)

Dentro de src/model/ existem dois arquivos já prontos: Usuario.java e UsuarioDAO.java. 

package model;

public class UsuarioDAO {

    public void inserir(Usuario usuario) {
        String sql = "INSERT INTO usuarios (nome, email) VALUES (?, ?)";

        try (Connection conn = Conexao.getConexao();
             PreparedStatement stmt = conn.prepareStatement(sql)) {

            stmt.setString(1, usuario.getNome());
            stmt.setString(2, usuario.getEmail());
            stmt.executeUpdate();
            System.out.println("[Sucesso] Novo usuário inserido no banco.");

        } catch (SQLException e) {
            System.err.println("[Erro] Falha ao inserir: " + e.getMessage());
        }
    }
}
Por que separar em Usuario e UsuarioDAO? Usuario é só o "molde" dos dados (nome, email...), sem lógica nenhuma — chamamos isso de Model. Já o UsuarioDAO é quem sabe conversar com o banco (inserir, buscar) — chamamos isso de DAO (Data Access Object, ou "objeto de acesso a dados"). Separar assim evita misturar "o que é o dado" com "como eu busco/salvo esse dado", o que deixa o código mais fácil de entender e de corrigir depois.

E o try/catch? O try é onde colocamos o código que pode dar erro (por exemplo, o banco estar desligado). Se der erro dentro do try, o Java pula direto para o catch, que "pega" esse erro e evita que o programa quebre — em vez disso, mostramos uma mensagem explicando o que aconteceu.

Passo 6 — Rodar o projeto

Abra o arquivo src/Main.java, clique no botão Run que aparece acima do método main (ou pressione F5). Se tudo estiver certo, o terminal vai mostrar a inserção de um novo usuário e depois a lista de todos os usuários do banco.
